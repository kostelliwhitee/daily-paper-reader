## 摘要
基于大语言模型的多智能体系统通过任务分解、智能体专业化、信息交换和中间验证来提升复杂问题解决能力。然而，现有系统通常将通信拓扑视为固定的设计选择或离线优化目标。我们提出了MANTA，一个多智能体网络拓扑自适应框架，使通信结构能够在推理时自我进化。在执行之前，MANTA从先前的结构经验中初始化一个任务条件化的拓扑。在部署期间，它监控协作轨迹，并在当前组织变得不足时应用有界结构更新。这些更新可以修改智能体角色、通信链路、执行顺序、信息可见性和验证路径，同时保持任务接口和智能体预算不变。我们在五个基准上对MANTA进行了评估，涵盖信息检索、工具使用、规划、工作流执行和数学推理，并与代表性的单智能体和多智能体基线进行了比较。MANTA取得了74.0的最高平均分，比最强基线高出5.8个百分点，并在PlanCraft上获得了最佳结果。这些结果表明，推理时的自我改进可以扩展到协作架构本身。

## Abstract
Large language model-based multi-agent systems improve complex problem solving through task decomposition, agent specialization, information exchange, and intermediate validation. However, existing systems typically treat communication topology as a fixed design choice or an offline optimization target. We introduce MANTA, a framework for Multi-Agent Network Topology Adaptation that enables communication structures to self-evolve at inference time. Before execution, MANTA initializes a task-conditioned topology from prior structural experience. During deployment, it monitors collaboration traces and applies bounded structural updates when the current organization becomes insufficient. These updates can modify agent roles, communication links, execution order, information visibility, and validation pathways while preserving the task interface and agent budget. We evaluate MANTA against representative single-agent and multi-agent baselines on five benchmarks spanning information seeking, tool use, planning, workflow execution, and mathematical reasoning. MANTA achieves the highest average score of 74.0, outperforming the strongest baseline by 5.8 percentage points and obtaining the best result on PlanCraft. These results show that inference-time self-improvement can extend to the architecture of collaboration itself.

**核心主张：**
- MANTA将通信拓扑视为系统在工作中可以改变的动态对象，而非部署前固定的设计选择，正式将其定位为“**拓扑级自我改进**”（Topology-Level Self-Improvement）。
- 论文论证了推理时的自我改进可以扩展到协作架构本身。在多智能体系统自我改进的层次体系中（输出→提示词→轨迹→技能/工具→记忆→智能体角色→拓扑→权重），MANTA聚焦于拓扑层面，填补了多智能体架构级在线自适应这一空白。

## 2. 方法论

**核心思想：**
MANTA是一个双层框架，包含两个嵌套层次：
- **目标多智能体系统**：通过推理、工具调用和消息交换解决实际任务。
- **编排层**：选择智能体、通信链路和信息可见性，而不直接解决任务本身。

**系统组成：**
MANTA将三类LLM组件与确定性代码相结合：
- **Topology Planner（拓扑规划器）**：负责初始拓扑设计及修复时的拓扑变异。
- **Trace Auditor（轨迹审计器）**：在每轮协作后扫描结构化痕迹，报告可观察的过程风险，而非答案正确性。
- **Skill Reflector（技能反射器）**：周期性重写长期经验文档。
- 确定性代码负责验证拓扑合法性、运行智能体、路由消息、控制修复和决定何时停止。

**拓扑表示：**
- 每个智能体具有**结构角色**（coordinator、worker、verifier、debater、voter）和**阶段角色**（worker或critic），还可接收领域人设和允许的工具列表。
- 智能体属于具有预定义交互结构的**模式组**（pattern groups），组可以嵌套，支持子组委派工作。
- **上下文策略**控制智能体可以访问的消息、发送者和共享证据，以及消息的传播距离和是否接收完整或摘要报告。
- 执行前验证组成员关系、附件循环、角色和智能体预算，非法提议被拒绝。
- 顶层模式包括：singleton（单例）、star（星型）、chain（链式）、debate（辩论）、voting（投票）。

**编排循环：**
1. **查询条件化规划（Query-conditioned planning）**：Planner接收任务和经验记忆，分析任务需求和可能的过程风险，输出包含交互模式、智能体数量及可选验证器或嵌套组的紧凑计划。确定性代码将该计划扩展为完整拓扑。
2. **轮次执行（Turn execution）**：按组结构递归执行拓扑，智能体通过结构化中继包（relay packets）通信（包含摘要、证据、置信度和未解决问题），共享上下文控制器强制执行每个智能体的可见性策略。去重相同工具调用，追加式证据账本保存跨分支的声明和支撑证据。
3. **轨迹审计与修复（Trace auditing and repair）**：每轮后，LLM审计器扫描结构化工件、工具记录、中继包、置信度、未解决问题和证据可见性。它不能访问基准答案或结果。若审计推荐修复（存在中等或高严重度的可修复标志），则Controller允许一次有界修复及最终轮次。修复操作包括：添加/扩展智能体、更改组模式、编辑通信边、更改信息可见性，每次修复最多3个操作。

**两时域记忆（Two-Horizon Playbook Memory）：**
- **短期行动手册（Short-term playbook）**：在单个运行内记录每轮使用的拓扑、审计标志、推荐的修复和Controller的决策，使Planner在修复时能看到已尝试的结构及其产生的异常。
- **长期行动手册（Long-term playbook）**：跨运行存储将任务特征和过程风险映射到拓扑选择的一般原则。每N轮运行后，Skill Reflector从最近执行迹线的摘要中重写经验教训。该学习循环只使用过程信号（如审计标志和是否达到决策级共识），**从不接触基准结果的ground truth**。

## 6. 主要结论与发现

**核心结论：**
1. **整体性能领先**：MANTA在5个基准上取得74.0的平均得分，比最强基线（ADAS的68.2）高出5.8个百分点，是唯一在信息寻求、工具使用、规划、工作流执行和推理五类任务上均表现均衡的方法。
2. **全面优于单智能体**：MANTA在所有基准上都超过了Single Agent，说明适应协作结构比单纯增强单智能体推理更具优势。
3. **消融发现**：
   - **初始拓扑规划贡献最大**（移除后从71.7降至57.5，降幅14.2个百分点）。
   - **拓扑修复次之**（移除后降至60.8）。
   - **长期行动手册**提供额外但较小的增益（移除或冻结约下降4-5个百分点）。
4. **变异预算效应**：所有基准随预算增加而改善，**第一次变异机会带来最大增益**，后续变异提供较小的边际收益，证明有界修复能扩展可解决任务的覆盖范围。
5. **记忆可迁移性**：MANTA的长期行动手册在跨域迁移（PlanCraft↔WorkBench）中产生平均+3.3个百分点的正增益，而基线方法（ADAS、AgentSquare、MASS）的迁移效果为中性或显著负面（MASS平均−58.3）。
6. **Token效率**：MANTA是评估的多智能体系统中整体token消耗最低的（77,652/运行），元级操作仅占约12%，说明精准的拓扑规划与修复不会引入大量额外开销。
7. **轨迹审计的有效性**：无修复标志的运行正确率为83.2%，有标志的为62.5%，分离度达20.7个百分点，表明过程信号确实携带答案可靠性的信息。审计器识别出117个不正确运行中的75个。
8. **修复的实际效果**：151次修复中60.9%减少了过程标志数量，59.6%的命名修复目标在下一审计中消失，修复后运行的正确率为69.5%。
9. **拓扑修复的多样性**：案例研究表明，有效的拓扑进化并不总是增加智能体数量——包括序列化执行（防止重复状态变更）、重连通信边（将星型转为完全连接辩论）、插入critic角色（为已有答案增加验证而非新增求解者）等多种非扩张性修复方式。

## 7. 方法或实验设计上的优点

**方法创新性：**
- **新问题定义**：正式提出“拓扑级自我改进”概念，将多智能体系统的通信结构从静态设计选择转变为执行时可调整的自我改进对象，拓宽了自我改进的研究边界。
- **双时域记忆机制**：短期行动手册支持运行内修复决策，长期行动手册实现跨运行的结构性经验积累，且**只使用过程信号而非基准结果**来学习，保持了知识迁移的泛化性。
- **有界、可验证的修复机制**：每次运行仅允许一次修复、每次最多3个操作，且所有变异必须通过结构验证，防止系统无限扩张或产生非法拓扑。
- **过程审计与正确性解耦**：审计器只关注协作过程中的可观察异常（如工具错误级联、过早共识、重复状态变更等），不接触基准答案，使拓扑修复可以推广到任意任务。
- **统计无状态设计**：智能体在阶段间无状态，所有对话状态存储在共享的追加式存储中；拓扑变异通过重新指向上下文控制器实现，无需迁移状态，使得变异“廉价且无损”。
- **确定性代码与LLM结合**：LLM负责高层推理（规划、审计、反思），确定性代码负责结构验证、消息路由和去重等，兼顾灵活性与可靠性。

**实验设计亮点：**
- **多层次评估体系**：除整体性能外，还有消融研究、变异预算分析、记忆迁移实验、审计效果统计、修复操作频率统计等，多角度验证方法的每个组件的有效性。
- **隔离式迁移实验**：在零变异预算下评估行动手册迁移，干净地分离了经验记忆对拓扑初始化的贡献。
- **过程标志的正确性相关性分析**：逐一统计每个过程标志与答案正确率的关联，为未来优化审计器的精度提供了数据驱动的方向。
- **详细的修复操作统计**：展示了各操作符的使用频率（如确定性检索收缩42.0%、更改组模式27.2%、扩展分支20.4%、添加智能体仅9.3%），有力论证了“修复更多改变执行结构而非增加智能体数量”的核心观点。

## 8. 不足与局限

**实验覆盖方面：**
- **基准规模较小**：每个基准仅30个任务，三次重复的标准差在某些基线上较大，可能影响结论的稳健性。
- **单一骨干模型**：仅使用Gemma 4 31B验证，未测试不同规模或不同家族的LLM（如GPT、Claude等），跨模型泛化性未知。
- **任务类型覆盖有限**：虽然涵盖5类任务，但缺乏真实的开放式交互场景（如多轮人机对话、复杂博弈、具身控制等）。
- **论文标题标记为2027年AAAI会议**，arXiv日期为2026年7月，GRPO和部分引用文献的时间线存在未来日期，这在当前时间线下属于预印本正常现象，但当读者在2026年审视时需注意论文未经过长周期同行评议验证。

**审计与修复的质量局限：**
- **审计正确性代理的准确性有限**：整体F1仅为0.47，某些基准（如BrowseComp）的FPR高达0.90，说明许多审计标志虽然指示了过程异常，但并未导致最终回答错误。这意味着修复可能被不必要地触发。
- **部分过程标志与正确性无关联**：“message_compaction_loss”（+2.2%差）和“tool_error_cascade”（+5.4%差）与正确率提高相关而非降低，说明审计分类的部分标志信号价值有限。

修复的因果归因不完整——论文只能证明修复后过程标志减少、正确率有所改善，但无法证明是特定修复操作直接导致了正确率提升；由于审计器存在一定误报、修复决策与任务难度可能相关，观察到的改善也可能混杂了选择偏差和回归均值效应，缺乏对单一修复操作因果效应的精确归因。

总体来看，MANTA在概念创新与工程闭环方面都达到了较高完成度：它将“多智能体以何种结构协作”从静态设定转变为可由系统自身在线调整的对象，并通过双时域记忆、过程信号驱动的有界修复和确定性验证机制，构建了可运行的拓扑级自我改进框架。在五大类基准上的实验不仅显示了整体性能的领先，也细致地剖析了各设计组件的贡献与代价。尽管基准规模、模型泛化性和审计精度仍有明显的改进空间，但其提出的问题定义、审计-修复机制以及记忆迁移思路，为后续多智能体架构级自适应研究提供了坚实的起点和可对照的基线。

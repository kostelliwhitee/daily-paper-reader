## 摘要
Top-$K$稀疏注意力通过仅关注少量键值(KV)条目来降低Softmax和值聚合的成本。然而，识别这一子集仍然需要对完整KV缓存中的当前查询进行评分，并执行全局Top-$K$选择，这使得选择器的成本随上下文长度线性增长，并限制了稀疏注意力在长上下文解码中的实际效率。在本文中，我们介绍了ReTopK，一种无需训练的方法，通过重用历史检索决策来加速动态Top-$K$注意力。ReTopK基于这样的观察：相似的查询通常关注重叠的支持集，而部分重叠的支持集仍然可以保留大部分精确Top-$K$注意力质量。对于每个注意力头，它维护一个有限的历史查询-支持对缓存，为每个新查询检索最相似的缓存查询，将它们的存储支持与最近窗口合并，然后仅使用精确的当前查询分数对生成的紧凑候选集进行重新排序。当重用不可靠时，基于相似性的回退机制会调用全历史精确Top-$K$，而定期精确刷新则限制缓存漂移。ReTopK保留完整KV缓存，仅重用选中的索引，而非历史分数、注意力权重或输出。在16K至128K上下文中，ReTopK在评估的近似方法中实现了最低的PG19困惑度，以及最高的NIAH和LongBench分数。在128K且$K=512$时，与精确Top-$K$相比，ReTopK仅增加了0.50%的困惑度，同时将注意力计算加速了3.07倍。

## Abstract
Top-$K$ sparse attention reduces the cost of Softmax and value aggregation by attending to only a small subset of key--value (KV) entries. However, identifying this subset still requires scoring the current query against the full KV cache and performing global Top-$K$ selection, leaving selector cost linear in context length and limiting the practical efficiency of sparse attention for long-context decoding. In this paper, we introduce ReTopK, a training-free method that accelerates dynamic Top-$K$ attention by reusing historical retrieval decisions. ReTopK builds on the observation that similar queries often attend to overlapping supports and that partially overlapping supports can still preserve most of the Exact Top-$K$ attention mass. For each attention head, it maintains a bounded cache of historical query--support pairs, retrieves the most similar cached queries for each new query, unions their stored supports with a recent window, and reranks only the resulting compact candidate set using exact current-query scores. A similarity-based fallback invokes full-history Exact Top-$K$ when reuse is unreliable, while periodic exact refreshes limit cache drift. ReTopK retains the complete KV cache and reuses only selected indices, rather than historical scores, attention weights, or outputs. Across 16K--128K contexts, ReTopK achieves the lowest PG19 perplexity and the highest NIAH and LongBench scores among the evaluated approximate methods. At 128K with $K=512$, ReTopK incurs only a 0.50\% perplexity increase over Exact Top-$K$ while accelerating attention computation by $3.07\times$.

## 1. 论文的核心问题与整体含义（研究动机和背景）

- **核心痛点**：Top-K稀疏注意力虽然通过只关注K个最重要键值（KV）条目，降低了Softmax计算和值聚合的成本，但**选择这K个条目的过程本身仍然需要扫描完整KV缓存并执行全局Top-K排序**。这意味着"索引发现"（index discovery）的成本随上下文长度线性增长，成为长上下文解码中的主要瓶颈。本文通过实验数据表明，在128K上下文下，完整QK评分和Top-K选择占据了Exact Top-K注意力延迟的95%以上。
- **研究动机**：作者观察到**相似的查询往往具有重叠的Top-K支持集（attention support）**，且部分重叠的支持集仍能保留大部分精确Top-K注意力质量。基于此观察，历史查询-支持对可作为紧凑的检索决策记录，使选择器无需每次解码都重新扫描完整历史。
- **整体贡献**：本文提出ReTopK，一种**无需训练**的加速方法，通过复用历史检索决策来避免重复的全量扫描，在保留完整KV缓存（不驱逐任何条目）的前提下，大幅降低动态Top-K注意力的索引发现成本，实现效率与质量的良好平衡。

## 2. 论文提出的方法论

- **核心思想**：**"先回忆，再排序"（Recall-Before-Rerank）**——利用查询相似性作为轻量级检索信号，从历史查询-支持对缓存中召回相关支持集，合并为紧凑候选集后，仅用当前查询的精确分数对候选集进行重排序，最终得到近似的Top-K支持集。

- **关键流程**（算法流程的文字描述）：
  1. **缓存维护**：为每个注意力头维护一个容量为C的FIFO查询-支持缓存，存储归一化查询向量及其对应的历史Top-K支持集（仅索引），在prefill阶段用最后C个prompt token初始化，并在每次解码步骤后更新。
  2. **相似性召回**：对当前查询，计算其与所有缓存查询的余弦相似度，取最相似的R个缓存条目。
  3. **候选集构造**：将R个检索到的支持集与一个近期窗口（最近W个token）合并、去重，得到紧凑候选集（大小约为RK+W）。
  4. **精确重排序**：仅对候选集内的键计算当前查询的精确QK分数（非历史分数），然后从中选择Top-K索引，用于后续的Softmax和值聚合。
  5. **可靠性保障**：
     - **相似性回退**：若最大缓存查询相似度低于阈值τ，则回退到完整历史Exact Top-K。
     - **定期刷新**：每Tr步执行一次完整Exact Top-K刷新，以注入精确检索决策并限制缓存漂移。

- **关键公式**：
  - 精确Top-K支持集：$S_t = \text{TopK}_{i \in \{1,...,L_t\}}\left(\frac{q_t^\top k_i}{\sqrt{d}}, K\right)$
  - 缓存结构：$\mathcal{B}_t = \{(\bar{q}_c, \hat{S}_c)\}$，$\bar{q}_c$为归一化查询，$\hat{S}_c$为历史支持集
  - 相似度计算：$\rho_{t,c} = \bar{q}_t^\top \bar{q}_c$
  - 候选集：$\mathcal{A}_t = \text{Unique}\left(\bigcup_{c \in \mathcal{R}_t} \hat{S}_c \cup \mathcal{L}_t\right)$，其中$\mathcal{L}_t$为最近窗口
  - 重排序支持：$\hat{S}_t = \text{TopK}_{i \in \mathcal{A}_t}(\hat{e}_{t,i}, K)$，其中$\hat{e}_{t,i}$是仅对候选集计算的精确当前查询分数

- **核心创新点**：
  - 仅复用历史**索引选择**，不复用历史注意力分数、权重或输出
  - 保留完整KV缓存，不驱逐任何条目
  - 每个注意力头独立维护缓存和检索决策（因为不同头的复用质量差异显著）
  - 复用步骤的选择器复杂度为O(Cd + Mtd)，与上下文长度解耦

## 6. 论文的主要结论与发现

1. **质量保持**：在128K上下文、K=512下，ReTopK相比Exact Top-K仅增加0.50%困惑度，同时在PG19上取得所有近似方法中最低的困惑度，NIAH和LongBench分数领先。
2. **效率提升**：ReTopK将注意力计算加速3.07倍（128K，K=512），且加速比随上下文长度增长而增大（16K时为1.29倍至128K的3.07倍）；在端到端解码中，加速比从128K的1.13倍提升至5M的3.73倍。
3. **跨模型一致性**：在Llama-3.1-8B和Qwen2.5-14B上，无需调参即可达到82.5%-89.6%的重用率，PPL变化范围-0.46%至+2.76%，加速1.26-2.66倍，证明方法在不同模型家族和规模上稳定迁移。
4. **支持集保真度与质量解耦**：虽然ReTopK仅达到56.9%的精确支持召回率，但保留92.4%的注意力质量和97.4%的头输出余弦相似度，说明未匹配的索引获得极低的归一化注意力权重，对最终输出影响有限。
5. **相似性信号的有效性**：缓存查询最大余弦相似度与保留质量和输出相似度正相关，验证了基于相似性回退的合理性。
6. **近期窗口的必要性**：移除近期窗口导致PPL从9.18急剧恶化至716（表3），说明近期token的保护不可或缺。
7. **相似性回退优于定期刷新作为质量保障**：移除相似性回退导致PPL从9.18升至10.08，而移除定期刷新对短期效果影响不大（9.19），但长时实验中定期刷新对限制错误累积有益。

## 7. 优点

- **优雅的"训练免费"设计**：无需任何训练或微调，即插即用于现有LLM，实用性强。
- **完整保留KV缓存**：与流式/驱逐方法不同，ReTopK不丢弃任何历史信息，能动态检索完整上下文中的相关条目，避免了不可逆的信息损失。
- **思想清晰且经过实证验证**：从"相似查询有重叠支持集"的观察出发，用实验数据（图2、图3）量化了该现象的普遍性与头部差异，并据此设计方法。
- **只复用索引，不复用分数/权重/输出**：所有注意力计算均基于当前查询的精确分数，避免了历史分数过期导致的累积误差。
- **双重可靠性保障机制**：相似性回退（处理低置信度查询）和定期刷新（限制长期漂移）互补，使方法在效率和质量之间可调。
- **工程实现扎实**：提供融合GPU实现，详细分析了内核融合各级别带来的加速贡献（L1至L5累计2.57倍），透明度高。
- **实验设计全面**：从质量、效率、泛化、消融、稳定性到超大规模端到端测评，覆盖了长上下文推理的关键关注点。

- **端到端加速受限于非注意力瓶颈**：论文承认在短上下文（128K）下非注意力部分占63.5%以上，ReTopK的端到端加速效果有限（1.13倍），仅在超长上下文（5M）下才达到3.73倍，不适用于短/中上下文推理。
- **理论保证不足**：论文未提供ReTopK重排序支持集相比精确Top-K在注意力质量上的理论保证（如近似比、误差上界），一旦遇到分布外查询或缓存被污染，缺乏可靠性保障。

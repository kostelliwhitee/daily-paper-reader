## 摘要
基于LLM的多智能体系统通过跨专业智能体之间交换消息来汇聚信息并做出决策。在每个智能体之间转发生成的所有消息会增加应用层流量。然而，这也会为智能体处理带来巨大的输入令牌，可能增加推理延迟和计算开销。现有方法尝试通过裁剪智能体或丢弃冗余消息来解决上述问题。然而，这种智能体级或消息级优化会导致最终决策的证据支持不足，或者仍然包含冗余消息传输。为了应对这些挑战，我们提出了BANDMAS，一个多智能体协作框架，将智能体间的通信建模为面向任务的数据流，通过因果启发的回放估值实现高效传输。具体来说，我们通过分析消息的语义特征（如证据和请求）将消息分解为多个数据包。系统仅当这些数据包的预测回放贡献超过其资源成本时才传输它们。因此，BANDMAS能够在满足带宽、延迟、截止时间和接收方上下文约束的同时，自适应地调度通信数据包。在冻结的Qwen3-4B流量上，跨SciFact、HotpotQA和FanOutQA数据集，我们的框架在选定上限下将应用层字节减少了53.2%至77.3%，并在所有三个工作负载上取得了受限方法中最高的平均任务指标。

## Abstract
LLM-based multi-agent systems make decisions based on the aggregated information via exchanging messages across specialized agents. Forwarding every generated message among agents increases application-layer traffic. Yet, it introduces tremendous input tokens for agent processing, potentially raising inference latency and computational overhead. Existing approaches attempt to address the above issues by pruning agents or discarding redundant messages. Nevertheless, such agent-level or message-level optimization results in insufficient evidence supporting for final decisions or still containing redundant message transmissions. To address these challenges, we propose BANDMAS, a multi-agent collaboration framework that models inter-agent communications as task-oriented traffic, which enables efficient transmission via causality-inspired replay valuation. Specifically, we decompose messages into several data packets by analyzing their semantic features such as evidence and requests. The system only transmits these packets if their predicted replay-derived contribution exceeds their resource cost. Consequently, BANDMAS is able to adaptively schedule communication packets while adhering to bandwidth, latency, deadline, and receiver context constraints. On frozen Qwen3-4B traffic across SciFact, HotpotQA, and FanOutQA, our framework reduces application-layer bytes by 53.2\% to 77.3\% at selected caps and attains the highest mean task metric among constrained methods on all three workloads.

## 2. 论文提出的方法论

### 2.1 核心思想
BANDMAS将每条消息按语义特征（如主张、证据、不确定性、请求）分解为**可追踪的语义数据包**（semantic packet），通过**因果启发的离线回放估值**（causality-inspired replay valuation）预判每个数据包对下游任务的贡献，仅当预测贡献超过其资源成本时才准入传输。

### 2.2 系统架构与关键流程

**（1）语义包化（Semantic Packetization）**
- 生成者（reader agent）在统一提示词契约下输出JSON对象，包含四个结构化字段：
  - **Claim**（主张）：由来源支撑的结论
  - **Evidence**（证据）：支撑主张的引文或内容
  - **Uncertainty**（不确定性）：置信度限制或未解决歧义
  - **Request**（请求）：对其他参与者或接收者的信息需求
- 确定性解析器将消息拆分为多个数据包，记录消息ID、路由、时间戳、截止时间、语义类型、来源归属（provenance）、段顺序、依赖元数据等。
- 使用紧凑UTF-8 JSONL序列化格式计算数据包的实际线缆开销（含包封装开销，而非仅载荷字符）。

**（2）因果启发的回放估值（Replay Causal Effect, RCE）**

离线阶段，通过对受控回放实验定义每个数据包的因果贡献：
- **充分性（Sufficiency）**：Δ_suf(p_i) = U(F_x({p_i}), x) − U(F_x(∅), x)，衡量该数据包单独使用时的边际效用。
- **必要性（Necessity）**：Δ_nec(p_i) = U(F_x(P_x), x) − U(F_x(P_x\ {p_i}), x)，衡量从完整上下文中移除该数据包时的效用损失。
- **RCE**：Δ(p_i) = ½[Δ_suf(p_i) + Δ_nec(p_i)]——取两者的平均值作为综合贡献标签。

RCE被明确界定为"上下文依赖、因果启发的画像标签"，而非无限制的因果效应或在线结果信号，且不捕捉高阶交互效应。

**（3）分裂安全（Split-Safe）价值预测**
- 部署阶段无法获得真实RCE（需要重放接收端结果），因此冻结一个**经验贝叶斯收缩预测器**：
  - 特征集仅包含**前结局元数据**（数据包类型、路由、词法标记、序列化大小、轮次位置），排除接收端输出、金标答案、评测分数等一切结局相关特征，保证**无结局泄漏边界**（no-outcome-leakage boundary）。
  - 收缩估计公式：bμ_g = (n_g/(n_g+α))·Δ̄_g + (α/(n_g+α))·π_g，其中α=6为固定强度，层级从全局均值逐步细化到类型-路由、词法标记、数据包大小、轮次等特征单元。
- 两种评分策略：
  - **因果策略**：s_causal(p) = bΔ(p)
  - **混合策略**：s_hybrid(p) = λ₁·Norm_x(bΔ(p)) + λ₂·q_sem(p)，(λ₁=0.75, λ₂=0.25)

**（4）静态与自适应调度**

- **静态模式**：按冻结分数排序，贪心准入完整数据包，确保序列化批量不超过线缆上限（wire cap），O(n²)精确批量核算。
- **自适应模式**：增加截止时间、排队延迟、接收端上下文和价格检查。资源价格按公式 λ_{k,t+1} = max(0, λ_{k,t} + η_k(u_{k,t}/C_{k,t} − 1)) 动态更新，仅基于已完成的服务观测，每个数据包的净值为：
  - g_t(p) = s_h(p) − λ_b,t·c_wire(p)/C_b − λ_ℓ,t·c_link,t(p)/C_ℓ − λ_q,t·c_ctx(p)/C_q
  - 排序复杂度O(n log n)，最坏情况下准入扫描O(n²)。

## 6. 论文的主要结论与发现

1. **BANDMAS在削减流量的同时保持甚至提升任务效用**：在选定上限下，应用层字节减少53.2%（FanOutQA）至77.3%（HotpotQA），同时在所有三个基准上取得受限方法中最高的平均任务指标（SciFact 0.679、HotpotQA 0.290、FanOutQA 0.234），均超过Full通信的对应值（0.617/0.273/0.219）。

2. **因果估值显著优于纯语义相关性排序**：配对检验显示，因果策略在任务指标上分别超越语义相关性0.236（SciFact）、0.157（HotpotQA）、0.105（FanOutQA），所有Holm校正后p<0.001；在HotpotQA和FanOutQA上的证据F1提升也显著。

3. **证据行为取决于基准结构**：在多源基准（HotpotQA/FanOutQA）上，因果调度显著改善证据F1；在SciFact上，证据F1与Full几乎持平（0.398 vs 0.397），说明"回答正确"与"保留支持证据"需要分别追踪。

4. **回放标签有一定预测力但并不完美**：正向RCE标签仅占34.8%-36.0%，约51.4%-59.4%的数据包为实测零贡献；预测器与真值的秩相关为0.480-0.538，有用包召回率0.522-0.582——这解释了为什么混合评分仍有竞争力，也说明"纯相关性不足、预测RCE有用但不完美"。

5. **类型化语义包边界优于逐句或逐消息**：在固定词法选择和接收端下，类型化字段（Claim/Evidence/Uncertainty/Request）在不同预算点均取得最高效用均值，同时避免了消息包过大无法装入剩余容量和句子包将主张与支持证据分离的问题。

6. **自适应调度在负载饱和后发挥作用**：低负载（ρ=0.50）时静态与自适应几乎无差异；高负载（ρ=1.00-1.50）时自适应调度通过已完成服务价格抑制更多数据包，降低p95尾部延迟（如SciFact ρ=1.50时p95从22,923ms降至18,793ms），但以任务效用下降为代价（SciFact任务均值从0.679降至0.618）——呈现**可调的延迟-效用权衡**而非无条件优势。

7. **字节削减不等于推理加速**：受限策略节省52.4%-77.3%字节，但预热后接收端延迟的下降幅度远小于字节节省比例，说明通信效率与计算效率需要分开评估。

8. **预测器具有跨模型迁移性**：在Qwen2.5-7B上因果排序依然保持最高任务和证据均值，说明学习到的包价值信号并非特定于单一模型的伪迹。

## 7. 优点

1. **粒度适当的问题分解**：将"哪些智能体参与"（拓扑）与"哪些消息内容传输"（内容准入）明确解耦，填补了智能体级剪枝与令牌级压缩之间的粒度空白。

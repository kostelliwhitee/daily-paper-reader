## 摘要
基于大语言模型（LLMs）构建的多智能体系统（MAS）正在迅速普及，但其异构执行轨迹缺乏跨方法评估的共同基础。仅基于结果的基准丢弃了协作信息，而基于大语言模型作为裁判（LLM-as-Judge）的评估需要额外的、依赖模型的推理，并且可能随大语言模型和评分标准而变化。我们引入了一个可泛化的评估框架，将原生多智能体系统轨迹映射到统一协作图的共享空间中，使得不同方法能够在相同的表示、参考集和指标面板下进行评估。候选图与针对特定查询的参考森林进行比较。每个森林是基准提供的已验证成功图的集合：它记录了代表性多智能体系统方法完成任务的多种方式，而不是规定唯一的最优过程。将该框架实例化为ForestBench，我们从七个公开数据集中筛选出844个需要协作的查询，为每个查询预计算十个成功的、以目标为条件的参考图，并评估六个代表性多智能体系统框架。受控的骨干、参考构建和扰动研究测试了评估的稳定性和范围。一旦构建了基准森林，ForestBench即可在毫秒内对轨迹进行评分，无需进一步的大语言模型推理，为比较不同的多智能体系统协作轨迹提供了可复用的结构化基础。

## Abstract
Multi-agent systems (MAS) built on Large Language Models (LLMs) are proliferating rapidly, but their heterogeneous execution traces provide no common basis for evaluation across methods. Outcome-only benchmarks discard collaborations, whereas LLM-as-Judge evaluation requires additional, model-dependent inference and can vary with the LLM and rubric. We introduce a generalizable evaluation framework that maps native MAS traces into a shared space of unified collaboration graphs, enabling different methods to be evaluated under the same representation, reference set, and metric panel. Candidate graphs are compared with a query-specific reference forest. Each forest is a benchmark-provided collection of verified-success graphs: it records diverse ways in which representative MAS methods can complete the task, rather than prescribing a unique optimal process. Instantiating the framework as ForestBench, we filter $844$ collaboration-necessary queries from seven public datasets, precompute ten successful target-conditioned reference graphs per query, and evaluate six representative MAS frameworks. Controlled backbone, reference-construction, and perturbation studies test the stability and scope of evaluation. Once the benchmark forests are built, ForestBench scores a trace in milliseconds without further LLM inference, providing a reusable structural basis for comparing diverse MAS collaboration traces.

## 1. 核心问题与整体含义（研究动机与背景）

- **背景**：基于大语言模型（LLM）的多智能体系统（MAS）正快速发展，涵盖固定流水线、动态角色分配、自组织群体等多种范式。然而，新框架的提出速度远超评估方法的发展。
- **核心痛点**：
  - **结果导向基准（Outcome-only benchmarks）**：如 GSM8K、MMULU、HumanEval，仅对最终答案打分，完全丢弃了多智能体区别于单智能体的核心特征——协作过程。
  - **LLM-as-Judge 评估**：依赖额外的、与模型和评分标准相关的推理，存在不可复现、费用高、结果随模型/提示词波动等问题。
  - **原生轨迹异构性**：不同 MAS 框架的事件模式（event schemas）、角色词汇（role vocabularies）和通信协议各不相同，难以直接横向比较。
- **核心问题**：领域缺乏一个统一的过程级（process-level）评估基础，使得异构方法无法在固定、可复现的评估空间中进行公平的横向比较。
- **提出方案**：ForestBench——一个可泛化的评估框架，将不同 MAS 的执行轨迹映射到统一的**协作图**（collaboration graph）空间，并基于基准预构建的、查询特定的**参考森林**（reference forest）进行确定性结构化评分。

## 2. 方法论：核心思想、技术细节与公式

### 2.1 核心思想
将每个 MAS 执行轨迹（trace）抽象为一个有向无环图（DAG），以节点代表动作、边代表信息流转；再用多种已验证成功的协作结构构成"森林"作为基准，通过候选图与森林的结构相似度来打分。核心在于**分离表示与评估**：任务正确性单独衡量，协作质量通过确定性图指标刻画。

### 2.2 关键技术细节

**（1）图抽象（Graph Abstraction）**

- 将轨迹 τ 映射为 G(τ) = (V, E, φ)：
  - V：每个原子动作一个节点；
  - E：动作间的信息传递边；
  - φ：节点标签（发出者、规范角色 r∈R、文本内容）。
- 由于动作带时间戳且只能消费已产生的信息，图天然为 DAG。
- 该抽象是有损的：丢弃框架特定的运行时状态和精确墙钟交错，但保留角色、动作和信息流依赖。独立动作的排序变化不会改变图结构，从而实现跨框架可比性。

**（2）参考森林（Reference Forest）**

- 每个查询 q 对应一个参考森林 F(q) = {(Gk, qk)}，其中 Gk 为已验证成功的协作图，qk 为质量权重（综合正确性、结构简洁性、token 成本）。
- 森林的设计体现了"同一任务存在多种成功协作模式"的理念，避免单一黄金过程带来对某种协调范式的偏袒。

**（3）核心指标：Forest Match（FM）**

- 首先计算候选图 G 与参考图 G′ 的**成对相似度**：
  - sim(G, G′) = α·s_node + β·s_edge + γ·s_topo，默认 (α, β, γ) = (0.4, 0.4, 0.2)
  - s_node：角色集合的 Jaccard 相似度
  - s_edge：角色类型化边的 Jaccard 相似度
  - s_topo：基于节点数和边数比值的拓扑相似度
- 然后对森林中所有参考图加权平均：
  - FM(G, F(q)) = Σ wk·sim(G, Gk) / Σ wk，wk 为归一化权重，最大值参考图为 1。
- 另报告 **Best Similarity**（距最近参考图的最大相似度），刻画与单个成功模式的接近程度。
- 全部指标都是图的确定性函数，**评估时无需任何额外 LLM 推理**。

**（4）辅助指标面板**

- **Node Validity（NV）**：被下游动作消费的节点比例，衡量动作是否被有效利用。
- **Mean Uptake**：下游内容对上游内容的语义采用程度（余弦相似度超过阈值）。
- **Content Redundancy（CR）**：基于归一化哈希的重复内容比例。
- **Tokens 与 Efficiency**：token 总消耗与拓扑效率（每活跃代理的并行度）。

### 2.3 算法流程（文字说明）
1. 运行候选 MAS 在查询 q 上，得到原生轨迹；
2. 使用适配器将轨迹解析为标准事件流（agent_message、tool_call、decision）；
3. 将事件流投影为协作图，并通过别名表将原始角色名映射到共享角色词汇表；
4. 将候选图与预计算的参考森林 F(q) 比较，计算 Forest Match、Best Similarity 及其他指标。

## 3. 实验设计：数据集、基准与对比方法

### 3.1 数据集与查询筛选

## 6. 主要结论与发现

- **图表示能分离结构差异**：6 个框架的准确率范围仅 0.038（0.531–0.569），但 Forest Match 范围达 0.105（0.316–0.421），说明最终答案掩盖了显著的协作结构差异。
- **参考森林提供稳定的结构信号**：跨不同骨干模型（Kendall τ=1.00）、留一生成器（τ=0.60–1.00）、无金标构建（τ=0.867）等条件下，聚合排序基本保持稳定。
- **指标面板补充准确率的盲区**：
  - Debate 准确率最高（0.569），但 Forest Match 最低（0.316）、Best Similarity 最低（0.284）、token 开销最大（3,227）——所谓"高准确性低结构对齐"；
  - AFlow 的 Content Redundancy 最高（0.167），反映其并行求解器的重复内容；
  - Swarm 的 Node Validity 为 0.968（唯一低于 1），存在有动作未被下游消费的现象。
- **不同任务类型适合不同协作模式**：Debate 在 SWE-bench-Verified 上 Forest Match 达到 0.382（排名第一），与代码补丁评审场景高度契合，说明结构信号对领域偏好敏感。
- **多智能体的收益依赖于骨干模型能力**：相对单智能体 CoT 基线，平均增益在 DeepSeek-V4 上为 −0.002，GPT-5.5 上为 −0.039，Claude-Sonnet-4.6 上为 −0.069——更强的骨干模型下，编排带来的平均收益为负，说明"加代理"并非普遍有益。
- **失败模式可归因于结构或内容**：部分失败源于协作结构不适合任务（缺角色/固定重复模式），另一部分则是结构合理但内容错误，两类问题需要不同的修复策略（前者调整拓扑，后者加强验证与聚合）。
- **成本优势显著**：参考森林构建完成后，每条轨迹的评估在毫秒级完成、零推理 tokens，比 LLM-as-Judge 快约 2,900 倍，且可无限复用。

## 7. 优点（方法与实验亮点）

1. **统一且无损关键信息的表示**：将异构 MAS 轨迹映射为角色化协作 DAG，既能保留谁协作、信息如何流动等关键信息，又对代理重命名和动作重排序不敏感。
2. **多元成功结构观（森林而非单树）**：参考森林承认多种成功协作模式并存，避免对特定范式（如流水线或辩论）的偏袒，方法论上更为公正。
3. **确定性、零推理成本评估**：所有指标都是图的确定性函数，评分无需额外 LLM 调用，成本低廉、完全可复现，解决了 LLM-as-Judge 的核心痛点。
4. **指标面板全面**：从结构对齐（FM/Best Sim）、协作有效性（NV/Uptake）、资源消耗（Tokens/Redundancy）等多维度刻画协作质量，并与准确率互补。
5. **充分且审慎的鲁棒性验证**：对骨干模型、参考生成器、金标条件、权重配置、TSP 阈值等做了系统消融，且对失败诊断的提示词敏感性有自觉反思。
6. **可复用的基准资产**：参考森林作为开源数据随基准发布，新方法可直接使用，无需重新构建成功轨迹，降低了后续研究的门槛。

## 8. 不足与局限性

1. **参考森林构建成本高**：一次性需消耗约 2,050 万 tokens，对配置有限的团队不友好；虽然一次付出可复用，但跨数据集扩展时仍需再次支付。

2. **单智能体可能被结构性不公平对待**：论文引入了"单智能体结构锚"（CoT-SC），但在 LOO 和消融设计中，单智能体的参考参与度有限，可能使其结构分偏低；更严重的是，一个设计良好的单智能体可能天然不具备多代理协作图特征。

3. **评估框架的周期性风险**：参考森林基于当前时代的 MAS 范式（辩论、群体、流水线等）构建，如果未来出现全新的、与这些范式完全不同但更优秀的协作模式，该模式的 Forest Match 可能偏低，基准会"惩罚创新"。

4. **语义指标与模型无关性的矛盾**：论文声称零 LLM 调用，但 Mean Uptake 使用语义嵌入计算余弦相似度，需要预计算的嵌入模型；角色映射的别名表也需要人工维护，跨语言/跨领域扩展时不完全自动。

5. **选择性偏倚（TSP 筛选的局限）**：TSP 依赖强 LLM 自主打分，不同 LLM 的选择结果可能不同；TSP 已验证其阈值敏感性，但未验证不同打分 LLM 之间的稳定性。筛选后的 844 个查询偏向高分解性、多步骤任务，可能无法代表一般场景。

6. **细粒度诊断可复现性有限**：LLM 失败诊断在细粒度标签上的 Cohen's κ 低至 0.129（结构失败），说明细粒度结论高度依赖提示词和模型；作者也因此只依赖粗粒度修复方向，细粒度诊断的实用价值有限。

7. **统计显著性缺失**：未报告置信区间或显著性检验结果；0.038 的准确率差异可能不具统计显著性，结论仍存风险。

8. **领域覆盖不均衡**：推理与多跳搜索占 80% 以上，代码与工具使用合计不到 21%，结论对软件工程等场景的推广可能受限。

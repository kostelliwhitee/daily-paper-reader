## 摘要
多智能体大语言模型（LLM）系统可能通过内部消息、工具参数、日志和持久化内存暴露受保护状态，即使其公开输出看似无害。现有的隐私提示、编辑方法和源代码级访问控制限制了表面内容或数据访问，但未规定合法的知情智能体应披露什么，或者该披露如何在下游被重用。我们引入了最小必要通信（MNC），一种类型化语义去分类协议，从应用编写的候选族中选择一个任务充分的披露，并将其绑定到明确的接收者、目的、转发、生命周期、日志和内存作用域。参考监视器在后续操作中强制执行这些作用域，而历史感知扩展则考虑了重复披露累积的推理风险。受控的语义连接、内存、探测和纵向实验表明，传统防御可以保持协议级效用，同时暴露大量额外的推断信号。在相同的接收文本下，MNC保留授权传递，同时阻止未授权转发、日志记录、持久存储和过期后检索，而这些是纯文本语义去分类器允许的。双骨干MAGPIE执行进一步表明，介导的披露会传播到后续的规划、工具使用、协调和内存检索。这些结果支持作用域约束语义去分类作为私有LLM智能体系统的实用通信边界。

## Abstract
Multi-agent large language model (LLM) systems can expose protected state through internal messages, tool arguments, logs, and persistent memory even when their public outputs appear innocuous. Existing privacy prompts, redaction methods, and source-level access controls restrict surface content or data access, but do not specify what a legitimately informed agent should disclose or how that disclosure may be reused downstream. We introduce Minimum-Necessary Communication (MNC), a typed semantic-declassification protocol that selects a task-sufficient disclosure from an application-authored candidate family and binds it to explicit recipient, purpose, forwarding, lifetime, logging, and memory scopes. A reference monitor enforces these scopes across subsequent operations, while a history-aware extension accounts for inference risk accumulated over repeated disclosures. Controlled semantic-join, memory, probing, and longitudinal experiments show that conventional defenses can preserve protocol-level utility while exposing substantial additional inference signal. Under identical receipt text, MNC preserves authorized delivery while blocking unauthorized forwarding, logging, durable storage, and retrieval after expiration that a text-only semantic declassifier permits. Two-backbone MAGPIE executions further show that mediated disclosures propagate through subsequent planning, tool use, coordination, and memory retrieval. These results support scope-bound semantic declassification as a practical communication boundary for private LLM-agent systems.

## 1. 核心问题与整体含义（研究动机与背景）

本论文聚焦于**多智能体大语言模型（LLM）系统中的隐私泄露问题**。作者指出了一个被忽视的关键事实：

- 多智能体 LLM 系统中，规划者、工人、工具调用、日志和持久化记忆之间传递的**内部轨迹**（消息、工具参数、日志、内存读写），可能泄露敏感状态。
- 即使**公开输出**（例如选定的会议时间、路由动作、任务回执）看似无害，内部信息的组合、模式或语义摘要仍可能揭示私密原因（如医疗、法律约束）。
- 现有防御（隐私提示、脱敏、事实级访问控制）只限制表面内容或数据访问，但从未明确回答两个核心问题：
  1. 一个**合法获知**私有数据的智能体，**应该向下游披露什么**？
  2. 这份披露如何被下游**转发、记录、存储和再次使用**？

本文的核心含义是：将“谁可以访问数据”与“访问后可以传递什么、传递后可以如何使用”区分开来，并提出一个可执行的运行时通信策略来约束后者。

## 2. 方法论（核心思想、关键技术细节、流程）

### 2.1 核心思想：Minimum-Necessary Communication（MNC）

MNC 是一个**类型化语义去分类协议**，它替代了“自由文本生成”的通信方式，将披露限制在**应用明确界定的候选族**中。

### 2.2 关键技术细节

**契约结构**（每条披露绑定一个合约）：

```
c = (p, r, F, ℓ, ϕ, μ)
```

| 符号 | 含义 |
|------|------|
| p | 授权目的（purpose） |
| r | 接收者（recipient） |
| F | 允许字段集合（fields） |
| ℓ | 生命周期（lifetime） |
| ϕ | 允许的下游汇点集合（forwading / logging / sinks） |
| μ | 是否允许写入记忆（memory） |

**选择流程**：

1. 应用根据私有状态 S 与公开任务上下文 Z，生成有限候选族：Dc = {d1, ..., dk}
2. **任务充分性验证**（validator）剔除无法支持接收者完成声明操作的候选
3. **风险模型**（risk function）对剩余候选估计披露风险
4. 选择最低风险且任务充分的候选：

```
d*_t = arg min R(d; H_t, Z)
s.t. valid_c(d) = 1, need(d, p, r) = 1
```

**核心变体**：

- **MNC-C**：只在当前通信边界执行一次披露合约。
- **MNC-L**（历史感知扩展）：结合历史 H_t，限制增量与累积风险：

```
ΔR_t(d) ≤ ε_t， ΣΔR_j ≤ B
```

其中增量风险定义为附加候选 d 后校准风险的**非负增量**（max{0, br(H⊕d, Z) − br(H, Z)}）。

- **MNC-D**（失败路径）：当没有候选满足效用与风险约束时，委托给可信代理、弃权或请求用户批准。

**参考监视器强制**：
- 每次操作 e = (s, r, p, ch, d, t) 在下发前检查接收者、目的、字段、渠道、过期时间。
- 转发要求下一汇点在 ϕ 中；记忆写入要求 μ=1；记忆读取重复目的与生命周期检查。
- 派生对象继承原来源，且不可扩展作用域：

```
F' ⊆ F, ϕ' ⊆ ϕ, ℓ' ≤ ℓ, μ' ≤ μ
```

### 2.3 反泄露度量

定义**超额攻击者准确率**：

```
ΔAcc = Acc(g(Y, T, Z) = S) − Acc(g(Y, Z) = S)
```

即：内部轨迹是否比公开输出提供了额外信息。评估目标取五攻击者中的最大泄漏：

```
L_max = max_{a∈A} L_a(S; T | Y, Z)
```

## 6. 主要结论与发现

1. **内部信道泄露是实质性且可度量的**：在原始共享策略下，最坏攻击者从完整内部轨迹中获得 0.326 的额外准确率，远超公开输出。
2. **传统防御不足以约束披露内容与重用**：脱敏和事实 ACL 能减少但无法消除泄漏；纯文本语义去分类器无法阻止二级使用（范围违规率 0.999）。
3. **MNC-C 在效用与隐私之间取得最佳任务平衡**：任务成功 0.567（比原始共享 +0.194，比语义去分类器 +0.242），超额泄漏降至 0.035，总约束满足 0.910。
4. **作用域强制带来独立于内容重写的增益**：在同时发布相同回执文本的条件下，MNC-C 将范围违规从 0.999 降至 0.004，同时保持 0.996 的授权传递成功率。
5. **历史感知与委托绘制隐私-效用边界**：MNC-L 将泄漏降至 0.026、MNC-L+D 至 0.017，但任务成功相应下降（0.473 / 0.378），形成可视的权衡曲线。
6. **委托可处理纠缠型任务**：MNC-L+D 在纠缠基准上恢复任务成功至 0.804，同时将禁止暴露降至 0.016，无安全回执检测召回率达 0.951。
7. **MNC 更节省资源**：平均 200 个 token/轨迹（比原始共享少 23.1%），延迟从 0.648s 降至 0.518s。

## 7. 优点

- **问题定义清晰**：明确区分“表面内容限制”与“披露内容 + 下游重用”两个维度，填补了隐私提示、脱敏与访问控制之间的空白。
- **方法可执行、形式化**：契约结构、作用域不可扩展性约束、累积预算都有严格的形式化定义，不是启发式文字约束。
- **类型化接口务实**：MNC 不需要模型在无限自由文本中找到全局最优披露，而是从应用编写的有限候选族中选择——这既可行又可验证。
- **分层实验设计严谨**：输出-内部配对、最大攻击者指标、聚类 bootstrap、模板不相交划分——实验方法学水平较高。
- **内容重写 vs. 作用域执行的隔离**：表 2 将披露文本固定、仅改变执行机制，清晰证明了 MNC 的独立价值。
- **诚实呈现权衡**：明确显示 MNC-L 和 MNC-L+D 的任务成功下降，而不是将委托和弃权算作成功；明确指出实时扩展中格式化失败的瓶颈。
- **证据边界透明**：主动声明哪些是诊断性实验、哪些是主结果，不混淆证据等级。

## 8. 不足与局限

- **骨干模型规模有限**：仅覆盖 7–8B 模型，未验证更大模型或商用 API 上的迁移性。
- **任务成功率偏低**：即使最佳策略 MNC-C，端到端任务成功仅 0.567，远低于生产级可用标准（尽管原始基线也仅 0.373，说明 MAGPIE 任务本身有较高难度）。
- **下游整合失败**：MNC-L+D 有 293 个下游重规划失败（vs. MNC-C 的 102 个），说明即使委托成功返回回执，协调器仍可能无法整合结果。
- **实时格式化瓶颈**：AgentLeak 扩展中自由形式 MNC-C 只能达到 0.640 任务接口成功，暴露了真实部署中的渲染与值复制问题。
- **攻击者集合有限**：5 个攻击者虽互补，但可能无法覆盖更复杂的推理型攻击者；隐私声明局限于评测集。
- **与现有生产系统无直接比较**：与 Fides/Maris 等 IFC 系统未做正面竞争评测，仅与“属性匹配的代理”比较，因此不能宣称优于生产系统。
- **依赖应用侧质量**：MNC 的有效性依赖候选族生成器、验证器、风险估计器与契约定义的质量；如果应用界面设计不佳（例如候选族不够丰富或验证器误判充分性），MNC 可能过度拒绝或泄漏。
- **依赖信任假设**：参考监视器假定通信边界可被中介、契约由可信权威发布；信道被完全监控的假设在现实多租户或去中心化环境中可能不成立。

## 摘要
多智能体LLM系统是一种新兴的网络工作负载，其快速部署引发了关于它们产生的流量模式的问题。与常规应用相比，这些系统在内部生成请求：单个用户任务可以引发一系列结构化的模型调用，其时间由协调逻辑而非用户到达率控制。目前尚不清楚为人类驱动工作负载设计的经典流量模型是否适用于此场景。我们提出了跨顺序、星形和全网状智能体协调拓扑的LLM调用到达间隔时间分布的经验表征，使用多层测量框架，每个拓扑重复运行500次。我们发现拓扑从根本上塑造了对LLM后端的请求到达过程：扇出协调引入了顺序执行中不存在的结构性双峰性，推理阶段组件最好用对数正态分布描述，而泊松指数零模型在所有拓扑中被明确拒绝。这些差异传播到推理和网络级指标。框架和分析流程已在https://github.com/dlamagna/agentraffic公开发布。

## Abstract
Multi-agent LLM systems are an emerging networked workload whose rapid deployment raises questions about the traffic patterns they generate. Compared to conventional applications, these systems generate requests internally: a single user task can induce a structured sequence of model calls whose timing is governed by coordination logic rather than by user arrival rate. It is not clear whether classical traffic models, designed for human-driven workloads, apply to this setting.   We present an empirical characterisation of LLM-call interarrival time distributions across sequential, star, and full-mesh agentic coordination topologies, using a multi-layer measurement framework over 500 repeated runs per topology. We find that topology fundamentally shapes the arrival process of requests to the LLM backend: fan-out coordination introduces a structural bimodality absent in sequential execution, and the reasoningphase component is best described by a log-normal distribution, with the Poisson exponential null model decisively rejected across all topologies. These differences propagate to inference and network level metrics. The framework and analysis pipeline are released openly at https://github.com/dlamagna/agentraffic.

## 1. 论文的核心问题与整体含义

- **研究背景**：多智能体 LLM 系统（Multi-agent LLM Systems）正成为一种新兴的网络化应用负载。与传统的、由人类用户请求驱动的应用不同，这类系统能在执行任务时**内部生成**新的 LLM 调用和智能体间通信。单个用户任务可能引发一系列结构化的模型调用，其时间间隔由系统的**协调逻辑**（coordination logic）而非外部请求到达率决定。
- **核心问题**：为人类驱动工作负载设计的经典网络流量模型（如 Poisson 模型）是否适用于多智能体 LLM 系统？协调拓扑（coordination topology）如何影响 LLM 调用的到达过程？
- **整体含义**：该研究延续了网络流量测量领域的经验主义传统（如 Leland 等人的以太网自相似性发现、Paxson 与 Floyd 对广域网 Poisson 假设的证伪等），首次系统性地刻画了协调拓扑对多智能体系统 LLM 调用到达过程的影响。研究表明拓扑结构是负载生成器的一部分，流量建模必须考虑协调逻辑，这对共享推理后端的排队延迟、API 网关、限流器、负载均衡器以及企业网络的规划与运营具有直接意义。

## 2. 论文提出的方法论

- **核心思想**：通过受控实验，将**协调拓扑**作为唯一的设计变量，同时保持智能体运行时、模型后端和监控栈不变，从而分离出拓扑对流量模式的因果影响。论文以 **LLM 调用的到达间隔时间（Inter-Arrival Time, IAT）** 作为主要流量建模指标。

  - **星型（Star）**：指定求解者先发言，其余智能体作为并行评审者被同时调用；
  - **全互联（Full Mesh）**：所有 N×(N−1) 个有向对等消息对在每个讨论轮次被并发提交。
- **统计建模方法**：
  - 对 IAT > 50 ms 的"推理阶段"成分分别拟合三类候选分布：**指数分布**（Poisson 零模型）、**Weibull 分布**、**对数正态分布（Log-normal）**；

## 6. 论文的主要结论与发现

1. **拓扑从根本上塑造 LLM 调用到达过程**：
   - **顺序拓扑**：产生同质的、秒级的单峰到达过程（均值 6.23 s，中位数 4.56 s）；
   - **星型拓扑**：产生**双峰分布**——53.3% 的间隔低于 50 ms（并行评审者扇出效应），但 p95 高达 20.74 s（推理阶段）；中位数塌缩至 0.41 ms；
   - **全互联拓扑**：时间上更压缩（均值 1.09 s，中位数 236 ms），38.2% 的到达间隔低于 50 ms，同时并发驱动完成令牌吞吐量从 110 tok/s 升至 364 tok/s。
2. **双峰性是扇出协调的结构性效应**：非顺序拓扑的 IAT 分布由两个结构上不同的成分组成——"扇出成分"（IAT ≤ 50 ms，由并行调度产生）和"推理成分"（IAT > 50 ms，由模型生成时间和上下文累积决定）。单一参数族无法描述完整的到达分布。
3. **推理阶段成分符合对数正态分布**：在全部三种拓扑中，对数正态分布取得最低 AIC；对顺序和星型拓扑也取得最小 KS 统计量。**指数（Poisson）零模型被决定性拒绝**——推理阶段的到达过程不具备无记忆性。对数正态的胜出与调用延迟是提示词长度、上下文累积、输出令牌数和批处理决策的**乘法效应**这一机制解释一致。
4. **跨层传播效应**：拓扑差异不仅在应用层可见，还传播至推理层（并发度、令牌吞吐量）和网络层（TCP 字节速率、突发性）。Spearman 相关矩阵验证了四个测量层在追踪相同的拓扑诱导变化上的一致性。
5. **实践启示**：平均任务率相同的两个系统，若一个串行执行而另一个并行扇出，对后端基础设施的负载特征可能截然不同。突发敏感型指标（IAT 百分位数、亚秒突发分数、并发峰值、扇出/推理混合比例）应作为聚合吞吐量的补充。协调元数据对流量追踪的解读至关重要。

## 7. 优点

- **选题新颖且重要**：多智能体 LLM 系统是新兴负载，论文率先将协调拓扑作为流量模式的结构性决定因素进行实证研究，填补了现有流量建模文献的空白。
- **方法论严谨**：
  - 采用受控实验设计，拓扑作为唯一变量，排除了其他混杂因素；
  - 多层级同步测量（应用/推理/容器/网络）有助于理解因果链条，而不仅是表面相关性；
  - 对分布拟合采取了统计上谨慎的做法：明确讨论了大样本下 KS 检验的局限性，使用统计量而非 p 值，并通过子采样验证稳健性；
  - 基于 3×IQR 的离群值剔除防止模型服务超时污染推理阶段分布。
- **开源发布**：测量框架和分析管线在 GitHub 上公开（AgenTraffic），可复现、可扩展，对后续研究有直接价值。
- **写作定位清晰**：论文不宣称量化结果具有普适性，而是聚焦于"拓扑如何影响到达过程"这一结构性问题，结论从经验数据中提炼得较为审慎。

## 8. 不足与局限

- **实验覆盖范围狭窄**：
  - 仅使用一个任务家族（AgentVerse 的讨论式任务）和一个模型（Llama-3.2-3B）；
  - 仅使用 4 个子智能体，未探索不同智能体数量对拓扑效应的影响；
  - 单一主机部署，未考虑分布式部署或多数据中心场景；
  - 协议上仅覆盖 HTTP over TCP/Docker bridge，未涵盖 RDMA、多路径等更复杂网络环境。
- **忽略非 LLM 调用流量**：论文明确说明只考虑了 LLM 调用，**外部工具调用（tool calls）、向量数据库查询、浏览器操作**等流量类别留待未来工作。这意味着对真实多智能体系统总流量的刻画尚不完整。
- **分布拟合的局限**：全互联拓扑下，Weibull 比对数正态取得更低的 KS 统计量（0.068 vs 0.089），说明"对数正态是所有拓扑下最优模型"这一结论在全互联场景下并不那么鲜明——作者承认 Weibull 能更精确地捕捉峰值，而对数正态更好地描述整体分布。
- **缺乏外部推广性**：作者自己承认表 2 和表 3 中的定量值（如 IAT 百分位数、突发比例）不能推广到其他配置。因此，论文提供的更多是**方法论模板和定性结构发现**，而非可直接套用的流量模型常量。
- **Poisson 零模型选择的潜在偏置**：论文以指数分布作为唯一的"传统"零模型，虽然这是流量建模的标准参照，但现代网络流量建模中还有其他值得对比的模型族（如 Pareto、自相似过程、马尔可夫调制过程等），论文没有展开更广泛的模型竞争。
- **未建模端点行为**：论文给出了分布描述，但没有构建完整的生成模型（如半马尔可夫模型）来完成从状态转移到 IAT 分布的概率性推理，作者将其列为未来工作。

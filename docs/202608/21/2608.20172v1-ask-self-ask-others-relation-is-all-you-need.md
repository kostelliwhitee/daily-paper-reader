## 摘要
注意力机制直接由成对分数导出归一化信息流。我们引入一种替代性的标记混合原语——关系，它首先将成对证据组织为显式的自我关系和交换关系，随后再导出信息流。这种关系组织衍生出全关系、快速关系、线性关系、混合关系以及一种键值风格的关系缓存。在约10M、30M和100M参数规模的匹配解码器专用模型中，全关系在三个规模上都取得了比多头注意力更低的最终验证负对数似然。在固定上下文参考基准中，快速关系的速度比物化全关系实现快3.60-4.41倍。在规模匹配的生产工作负载中，它在执行全关系算子的同时达到了PyTorch FlashAttention吞吐量的76.4-84.9%。混合关系使用75%的线性关系层，并实现了强大的语言建模质量。这些结果支持一种以关系为先的标记混合观点：问自己，问他人，然后让信息流遵循关系。

## Abstract
Attention directly derives normalized information flow from pairwise scores. We introduce Relation, an alternative token-mixing primitive that first organizes pairwise evidence into explicit Self and Exchange relations and derives information flow afterward. This relational organization gives rise to Full Relation, FlashRelation, Linear Relation, Hybrid Relation, and a KV-style Relation Cache. Across matched decoder-only models at approximately 10M, 30M, and 100M parameters, Full Relation achieves lower final validation NLL than MHA at all three scales. In a fixed-context reference benchmark, FlashRelation is 3.60-4.41x faster than the materialized Full Relation implementation. Across scale-matched production workloads, it reaches 76.4-84.9% of PyTorch FlashAttention throughput while executing the Full Relation operator. Hybrid Relation uses 75% Linear Relation layers and achieves strong language-modeling quality. These results support a relation-first view of token mixing: ask Self, ask Others, then let Flow follow Relation.

## 1. 核心问题与整体含义（研究动机和背景）

- **核心问题**：标准缩放点积注意力（MHA）将“关系形成”和“信息流动分配”压缩到同一个 `U → F` 步骤中，即每个 token 对的交互只用一个标量分数同时编码关系结构和决定信息流量。这导致 token 交互中异质的关系结构（如自我关系、与其他 token 的历史关系）没有被显式区分和建模。
- **研究动机**：作者认为，注意力不应是唯一的 token 混合原语；关系应该先于流动（Flow follows Relation）。即应先将成对证据组织为显式的“自我（Self）”和“交换（Exchange）”关系，再从中导出归一化信息流。
- **整体含义**：论文提出一种新的 token 混合原语 **Relation**，并验证了“关系优先”的建模方式在语言建模质量、执行效率和混合架构上均可行，支持“问自己，问他人，然后让流动跟随关系”的视角。

## 2. 方法论：核心思想、关键技术细节

### 2.1 核心思想
- 将 token 间的成对关系分解为两种最小结构角色：
  - **Self**：token 与自身的关系，位于矩阵对角线上。
  - **Exchange**：token 与历史中其他 token 的关系，位于因果下三角区域。
- 先构建显式的因果关系矩阵 `R`，再对 `R` 做 Softmax 得到信息流动 `F`，最后用 `F` 对信息状态进行加权传输。

### 2.2 Self–Exchange Relation（SER）
- 输入投影：
  - `P1 = XW1`, `P2 = XW2`, `I = XWI`
  - `P1` 和 `P2` 使用 RoPE 旋转，`I` 不旋转。
- 成对证据：`Uij = p1,i^T p2,j / sqrt(dh)`。
- 关系构造：
  - `Si = σ(Uii / τS)`，`τS = 2`。
  - `Eij = SiLU(Uij)`。
  - `Rij = Si (j=i), Eij - λℓ log i (j<i), -∞ (j>i)`。
  - 其中 `λℓ` 是逐层可学习的计数校准系数，用对数项校正可见历史数量带来的偏差。
- 信息流动：`Fi = Softmax(Ri)`, `Yi = Σ_{j≤i} Fij Ij`, `Xℓ+1 = Xℓ + Y WO`。

### 2.3 Multi-Head Relation（MHR）
- 将 `P1`, `P2`, `I` 划分为 H 个头，每个头独立执行 SER 构造。
- 在信息分支上引入**可学习 Givens 旋转**对相邻头对进行混合，头对配对模式在层间交替（`MA→MB→MA→…`）。
- 各头输出拼接后经 `WO` 投影回残差流。

### 2.4 关系流动的精确分解
- 定义历史 Exchange 对数归一化子 `LEi`、计数校正后的聚合 `Ai`、整行归一化子 `Zi`。
- 归一化流首先在 Self 质量 `Fii` 和聚合 Exchange 质量 `gi` 之间分配：`Fii = σ(Si - Ai)`, `gi = σ(Ai - Si)`, `Fii + gi = 1`。
- 条件于 Exchange，历史位置上的分配由 `πEij = Softmax_{j<i}(Eij)` 决定，且计数校正在历史位置间抵消。
- 最终信息传输可精确分解为：`Yi = (1-gi)eIi + gi * (历史 Exchange 信息摘要)`。

### 2.5 实用化变体
- **Full Relation**：显式的 token-to-token 算子。
- **FlashRelation**：利用上述分解，采用类似 FlashAttention 的因果分块扫描（tiled scan），不物化完整的 `U/R/F` 矩阵，在线维护 running max、normalizer 和信息累加器，实现与 Full Relation 完全等价的执行。
- **Linear Relation**：将历史 Exchange 压缩为循环状态 `Ct ∈ R^{dh×dh}`；顺序为 Ask Self → Ask Others → Answer → Become Others；使用 KDA 风格的通道级 retention 参数化，读取在写入前完成，保证严格历史支持。
- **Hybrid Relation**：在同一个 decoder 中混合 Linear 与 Full Relation 层（例如 `(LLLF)^3`，75% 为 Linear 层）。
- **Relation Cache**：自回归解码时只需缓存历史 `P2` 和 `eI` 状态（KV 风格），无需缓存 `P1`, `U`, `R`, `F` 等。

## 6. 主要结论与发现

- **Full Relation 优于 MHA**：在 10M、30M、100M 三个规模上，Full Relation 的平均最终验证 NLL 均低于 MHA，改善分别为 0.0412、0.0151、0.0310。在 9 次配对比较中赢得 8 次。
- **FlashRelation 高效**：固定上下文 T=1024 下，比物化 Full Relation 快 3.60-4.41 倍；在规模匹配生产负载下达到 PyTorch FlashAttention 的 76.4%-84.9% 吞吐，且执行的是精确的 Full Relation 算子。
- **Linear Relation 可行**：复杂度为 O(T d²/H)，decode 状态 O(d²/H)，在长上下文（至 T=32768）下吞吐可扩展。
- **Hybrid Relation 质量强**：75% Linear 层 + 25% Full 层的配置，在 30M 类设置下获得 1.2780 NLL，优于同规模 MHA 和 Full Relation，说明线性与全关系层可以良好组合。
- **总体结论**：关系优先的 token 混合是注意力的可行替代，且有多种高效实现，支持“先问自我，再问他人，最后让流动跟随关系”的观点。

## 7. 优点

- **概念清晰**：将关系显式分解为 Self 与 Exchange 两种角色，提供了新的归纳偏置，比直接注意力多了一个可解释的“关系形成”阶段。
- **数学分析深入**：精确推导了 Self–Exchange 流的分解、计数校正的抵消效应、以及 FlashRelation 的扫描不变量，为工程实现提供了坚实基础。
- **工程变体丰富**：从 Full 到 Flash、Linear、Hybrid、Cache 一应俱全，覆盖了不同计算/存储权衡，展示了框架的泛用性。
- **实验规范**：使用匹配配置、配对种子、多组消融和系统级吞吐测量，整体可信度较高。
- **结果差异化**：不仅报告了平均优势，也诚实地给出了逐 seed 的波动和个别劣势情况。

## 8. 不足与局限
